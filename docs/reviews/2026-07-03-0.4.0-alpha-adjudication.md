# 0.4.0-alpha — adjudication of the external release review

Date: 2026-07-03. Reviewed artifact: PR #95 (head `e1a91b8`) against `main`
`a0d6c6a`, plus the external reviewer's (Codex) eight findings and seven
recommended actions. Every decision below was re-derived from first
principles and re-verified against the repository, the live GitHub state,
and primary documentation before any correction was implemented. Baseline
on this branch before changes: `tools/check.sh` → ALL GATES GREEN
(1146 passed / 2 skipped), PHI scan clean.

## The review's verdict — ACCEPTED

"REJECT PR #95 as written" is correct, and independently confirmed:

- **Live evidence.** The repository runs CodeQL via *default setup* (the
  dynamic `github-code-scanning/codeql` workflow, enabled 2026-07-02).
  Default setup does not read a committed `.github/codeql/codeql-config.yml`
  — that file is only honored by an advanced-setup workflow via the init
  action's `config-file` input (GitHub code-scanning reference docs). PR
  #95's central artifact was therefore inert regardless of its syntax.
- **Syntax.** `query-filters` entries filter on query *metadata* (`id`,
  `tags`, …). A nested `paths:` under an exclude entry appears in no primary
  documentation; `paths`/`paths-ignore` are separate top-level keys that
  scope the *analysis*, not a single query. The PR's config would not have
  done what its comments claimed even under advanced setup.
- **Honesty regression.** The PR's SECURITY.md section stated an
  unconditional `0o700` guarantee while `core/output.py` makes the chmod
  POSIX-only. On `main`, SECURITY.md was truthful ("0o700 on POSIX") — the
  overclaim entered *with* the PR. A security document that promises more
  than the code delivers is a defect even when no code changed.
- **Salvage.** The PR's seven inline PHI-BY-DESIGN annotations are good
  practice; they are re-landed here, corrected and paired with *executable*
  inline suppressions.

Disposition: PR #95 is superseded by this branch and should be closed.

## Finding-by-finding

### F1 (P1) CodeQL suppression config — ACCEPTED, fixed stronger
Implemented as: a committed **advanced CodeQL workflow** (scheduled + push +
PR) with `security-extended`, the `advanced-security/python-alert-suppression`
query pack (inline-suppression evaluation is not documented as automatic, so
it is enabled explicitly), and **inline `# codeql[rule-id]` comments at
exactly the audited by-design sites** — no rule is excluded repo-wide, so
both rules keep protecting every other module. Constraint verified against
GitHub docs: while default setup remains enabled, advanced SARIF uploads are
rejected ("Upload with CodeQL results rejected due to 'default setup'"), so
one one-time owner action is required — disable default setup in repo
settings — and is documented rather than papered over. Rationale: a
suppression the tooling does not execute is worse than none; an auditable
posture requires the mechanism to be real.

### F2 (P1) Windows `0o700` claim — ACCEPTED; implemented, not re-worded
The reviewer allowed either ACL hardening or doc qualification. Qualification
alone would leave the flagship platform (the Windows installer) weaker than
the README's promise, so hardening was implemented: `secure_output_dir` now
strips ACL inheritance and grants only the current user, SYSTEM, and
Administrators on Windows — the exact posture CPython adopted for
`os.mkdir(mode=0o700)` in the CVE-2024-4030 fix and Win32-OpenSSH uses for
key material (verified against the CPython commit and the Win32-OpenSSH
wiki). Mechanism: `icacls` with literal SIDs (localization-safe, no pywin32
supply-chain addition; the OWNER-RIGHTS SID is avoided — it is a known
interop breaker). Fail-safe ordering (grant before inheritance strip) means
no failure mode can lock the operator out; ACL-less filesystems (FAT32/
exFAT) degrade to a loud warning plus the PHI-warning README. Docs now state
the per-platform truth.

### F3 (P1) CS50 packet — ACCEPTED, shaped "for CS50, not scoped to it"
Verified against the CS50x 2026 pages: the final project README must carry
title, video URL, and a multi-paragraph description covering what each file
does and design choices; AI assistance is permitted for the final project
provided "the essence of the work" is the student's own and its use is cited
"in the comments of your code." Implemented: a README CS50 section (video
placeholder until submission), `DESIGN.md` (architecture, debated decisions,
hardest problems, authorship & provenance table, "what the author personally
built"), and a one-line AI-assistance citation comment in every authored
source file — phrased to serve any reader, not just a grader. Commit
authorship remains the author's own identity; AI assistance is disclosed in
`paper/paper.md`, the README, and `DESIGN.md`.

### F4 (P2) PHI-bearing log filenames/paths — ACCEPTED IN SPIRIT, CORRECTED IN FACT, EXTENDED
An exhaustive audit of all 169 logging/print call sites found the review's
specifics were 1-for-4: the real leak is `deliver/archive/archive.py`
(`indexed pdf missing on disk: %s` with a `{family}_{given}_{dos}.pdf`
filename — line 257, not 262); the other three cited sites log
operator-chosen paths, not patient-derived values. The audit also surfaced a
worse, unreported defect: **`configure_logging()` — the only code that
installs the RedactionFilter — was never called anywhere**, so production
logging ran unredacted through `logging.lastResort` and the SECURITY.md "log
redaction" control was effectively dormant. Fixed: the leak site now logs
the opaque patient id; the redacting handler is installed at both entry
points (CLI callback, GUI main) idempotently; the filter learned the
`MM-DD-YYYY` filename date shape; remaining path-interpolating messages were
aligned with the repo's own stated convention ("never a path under
out_dir"); and a pipeline-level regression test asserts no fixture patient
name can appear in any log record.

### F5 (P2) Contradictory security docs — ACCEPTED
One SLA: the root SECURITY.md's 72-hour acknowledgement is canonical;
`docs/SECURITY.md` now defers to it. `docs/PLAN.md`'s CodeQL backlog line
now states the actual state (advanced workflow committed; semgrep still

### F6 (P2) Missing DESIGN.md — ACCEPTED
`DESIGN.md` added at the root: architecture, data model, genuinely debated
design choices, hardest problems, verification strategy, releases, and the
authorship/AI/provenance record with a per-component table.

### F7 (P3) Review-archaeology prose — ACCEPTED
The sweep found 41 sites (38 review-history tokens + 3 stale PR-tag tokens)
across src/, tests/, tools/, and CI. All rewritten as invariant comments —
the *property* each test pins, not the review that requested it. A CI-lane
test now bans review-archaeology tokens from code and workflows (docs/ and
CHANGELOG remain the sanctioned home for history — including this file).

### F8 (P3) Playwright pin drift — ACCEPTED, single-sourced
`packaging/constraints.txt` is now the one pin (`playwright==1.56.0`),
consumed via `pip install -c` by both the CI e2e lane and the Windows
packaging build, whose browser-cache key derives from the file's hash. A
drift test pins: single pin, both workflows reference it, no stray literal
pins, and the open library floor (`>=1.46`) ≤ the pin. Policy (library users
float, builds pin) is documented in the file and pyproject. Verified
context: each Playwright release pins exact browser builds, so the pin is
also the Chromium-golden pin.

## Reviewer's recommended actions

Actions 1–6 are implemented by the streams above. Action 7 ("post-beta
refactor") was **pulled forward into this release** by owner decision: the
CLI command groups and `UploadConsole.upload_start` are split behind stable
facades with every public import path, monkeypatch seam, entry point, and
packaging target preserved (pinned by the existing import-boundary and
parity tests). The PF mapper was evaluated and deliberately **not** split:
it is already decomposed into ~20 focused per-resource functions and its
outputs are pinned byte-identical by goldens — splitting the file would be
churn, not consolidation.

## Decisions beyond the review

- **Version.** This release is `0.4.0`, presented as **0.4.0-alpha** (the
  fourth alpha), continuing the project's convention (0.1–0.3 shipped as
  plain versions with alpha framing and the Alpha trove classifier). A
  literal PEP 440 pre-release was rejected: `0.4.0-alpha` normalizes to
  `0.4.0a0`, and pre-releases are excluded from default pip/pipx resolution
  — users running the README's install line would silently get 0.3.0.
  Windows VERSIONINFO resources are numeric-only regardless. The GitHub
  release is flagged pre-release; **beta is reserved for the CS50
  submission cut**.
- **No new feature surface in 0.4.0-alpha.** The differentiators (layout
  learner, L0–L6 ladder, lossless-or-refuse ingest, evidence-or-refuse
  registry) are already in. This release's job is trustworthiness: security
  truth, attribution integrity, product completeness.
